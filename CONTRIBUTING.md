# Contributing to fortifyjs

First off, thank you for considering contributing to `fortifyjs`. It's people like you that make `fortifyjs` such a great security tool.

## Where do I go from here?

If you've noticed a bug or have a feature request, make sure to check our [Issues](https://github.com/Chiranth-Janardhan-moger/fortifyjs/issues) to see if someone else has already created a ticket. If not, go ahead and [make one](https://github.com/Chiranth-Janardhan-moger/fortifyjs/issues/new).

## Fork & create a branch

If this is something you think you can fix, then fork `fortifyjs` and create a branch with a descriptive name.

## Get the test suite running

Make sure you have Node.js installed.
Run `npm install` to install dependencies.
Run `npm test` to ensure all tests pass.

## Coding Standards

- **Zero Dependencies**: Do not introduce any new dependencies.
- **Fast Execution**: All checks should remain highly optimized with low overhead.
- **Testing**: Maintain high test coverage and include tests for any new payloads or bypasses.

## Implement your fix or feature

At this point, you're ready to make your changes. Feel free to ask for help; everyone is a beginner at first.
Please make sure to add tests for your changes.

## Make a Pull Request

At this point, you should switch back to your master branch, make sure it's up to date with `fortifyjs`'s master branch, then merge your feature branch into your master branch. Next, push your master branch to your fork on GitHub and create a pull request!
